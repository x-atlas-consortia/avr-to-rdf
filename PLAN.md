Goal:

Convert the Antibody Validation Report records into validated, linked open data in RDF format.

Key information:

* AVR stands for Antibody Validation Report
* SOP for creating AVRs: https://zenodo.org/records/20543394
* AVR documentation: https://docs.hubmapconsortium.org/avr/index.html
* AVR structure: https://docs.hubmapconsortium.org/avr/tsv-format-v2.html
* The "json schema" for AVRs (in JSON format): https://open.metadatacenter.org/templates/https%3A%2F%2Frepo.metadatacenter.org%2Ftemplates%2F312f7be0-9aec-4cae-b942-a8864c0aa1ce
* The data conforming to the schema that we want to convert to RDF: https://avr.xconsortia.org/antibodies 
* OpenAPI spec for the https://avr.xconsortia.org/antibodies endpoint: https://github.com/x-atlas-consortia/avr-ui/blob/main/antibody-api-spec.yaml

Technology decisions:

* Implementation is as a python cli
* Uses LinkML (latest version) to convert from JSON to RDF (and more)
* The python program will download the data from https://avr.xconsortia.org/antibodies perform some normalization to get it into a LinkML form, save it as YAML. 
* All generated data will be published to a /dist/ dir locally and copied to a /docs/ dir in the gh-pages branch for GitHub Pages publishing
* What day the process was run on to create the output goes in /dist/CREATION_DATE
* Put LinkML schema outputs to /dist/schema/ .. include json-ld context, json schema, owl, ERD diagrams, and other useful LinkML schema documentation here with an index.html page linking to all that. Initially will live on github pages (relative dir /avr-to-rdf).
* Put data conversion outputs to /dist/data/ .. including the original json from the api endpoint, the yaml in linkml-compatible form, a json version with attached json schema and json-ld context as generated by linkml, RDF formats: turtle, owl, json-ld, and n-triples.

Data normalization scope:

* Minimal normalization: convert plain strings to IRIs/CURIEs, minimal validation
* Use standard biomedical ontologies first (OBO, CHEBI, Identifiers.org) for namespace mappings
* Unmapped terms fall back to HuBMAP-specific namespace
* No deduplication, reference resolution, or quality scoring at this stage

RDF output priorities:

* Primary formats: Turtle and JSON-LD
* Also generate: OWL and N-Triples for completeness

Validation:

* Include custom validation rules beyond LinkML schema (required fields, IRI format checks, etc.)

GitHub Pages structure:

* Handcraft index.html templates
* Auto-populate with dynamically generated file lists from output directories

Tasks:

* generate the base project
* create a linkml schema that can represent the AVR data, but also ensure linked open data concepts are adhered to like converting plain strings into IRIs and/or CURIES.
* write code to download the data, validate, transform, run through linkml, and produce clean output to /dist for publishing
